# Me² website — standing rules

One-page sales site for Me² (mesquaredagency.com). Primary goal: the visitor clicks **Talk to us** (a mailto to the contact email in v1). BRIEF.md is the full spec; read it before changing anything.

## Where things live (never hardcode them elsewhere)
- Client identity (name, domain, emails, booking URL): `src/config/site.config.ts` only
- Copy and section order: `src/content/site.ts` (word for word from BRIEF Appendix A). Don't rewrite copy unless asked; suggest instead.
- Page titles and descriptions: `src/data/routes.json`. Sitemap, robots.txt and llms.txt are generated by `scripts/postbuild.mjs`; never hand-edit `dist/`.
- Design tokens: `src/styles/tokens.css`. Only the text/background pairs in BRIEF §5 are allowed.
- Flags: `src/config/flags.ts`. Never remove a fallback; the site must look complete with every flag off.
- Logo: `src/assets/brand/` (run `npm run brand` after replacing the supplied file).

## Brand rules
- Visible name is always `Me²`. "Me Squared" only in alternateName, aria-labels and mailto subjects. Never ME2, Me2, MeSquared.
- Australian English, sentence case, plain-spoken. Banned words: revolutionary, game-changing, supercharge, seamless, cutting-edge, unlock, guarantee, guaranteed. Grep changed copy before committing.
- Never invent names, testimonials, statistics, results, logos or prices. Never name individuals. Real estate appears only in its own section.
- No stock photos, AI-generated people or property imagery. Never use the designer's reflected "we" logo concept or the "from me to we." tagline (not approved).
- Forms collect contact details and a short task description only; never fields for financial, health or identity information.

## Design
Direction (BRIEF §5, v0.8): an established business-services look inspired by intelligentoffice.com: navy hero with icon bubbles, centred heads with letter-spaced labels, light/bold mixed headings, rounded dark panels, white icon cards on grey. EC rejected a minimal type-only version as "atrocious"; don't drift back to sparse. Refine within this; mock up one page and get EC's yes before any wider restyle.
Don't give custom styles class names that are Tailwind utilities (ring, shadow, border, container, hidden...).

## Dependencies
Allowed: astro, typescript, @astrojs/check, tailwindcss, @tailwindcss/vite, @fontsource-variable/instrument-sans, @fontsource-variable/outfit, sharp; dev: @playwright/test, @axe-core/playwright, lighthouse, linkinator, wrangler; Phase 2: resend. Anything else needs a line in DECISIONS.md.
Out of scope: CMS, auth, database, client-side routing, UI frameworks, animation/icon libraries, carousels, chat widgets, cookie banners, newsletter signup, Google Fonts CDN, third-party scripts.

## Git and deploys
- Branch + PR for every change. Run `git branch --show-current` right before every commit and push; other sessions may share this checkout.
- Never push to `main` once it's connected to Cloudflare Pages (it deploys the live site). EC merges.
- Plain-English commit messages: what changed for the visitor, then why.
- Ask EC before merging, deploying to production, DNS changes, or anything that emails real people.
- Wrangler on this PC is signed in to the APN Real Estate Cloudflare account, not tech@mesquaredagency.com: never deploy from it.

## Verifying a change
`npm run verify` builds the real site and the test (fixture) builds and runs all 113 checks: copy word for word, flags, links, axe, keyboard, Lighthouse, schema, sitemap, no hardcoded identity. Report in `.verify/report.md`, screenshots in `screenshots/`. Then look at `screenshots/real-375.png` and `real-1280.png` yourself. `npm run verify -- --quick` skips Lighthouse and the link crawl. Update the matching docs/ file and the README launch checklist in the same change.
- Stock photos are atmosphere only (docs/media.md); never caption them as Me²'s team, office or clients.
- The logo SVGs in `src/assets/brand/` are the source for `logo.png`, favicons and the OG image: run `npm run brand` after changing them.
