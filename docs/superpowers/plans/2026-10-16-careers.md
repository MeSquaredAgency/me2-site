# Careers Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/careers/`, one page per role, and an application form whose submissions (with the CV attached) are emailed to people@ through the Worker.

**Architecture:** Role copy and careers wording live in one pure-data file (`src/content/careers.ts`) that both the Astro pages and the Worker import. One rest-param route (`src/pages/careers/[...slug].astro`) builds the index, the role pages and the two outcome pages, each view in its own component. A new Worker module (`worker/applications.ts`) checks applications and sends them through Resend, mirroring `/api/enquiry`.

**Tech Stack:** Astro 7, TypeScript (strict, `allowImportingTsExtensions`), Tailwind v4 tokens, Cloudflare Workers (static assets + `worker/index.ts`), Resend HTTP API, Playwright + axe for checks (the repo's `scripts/check-*.mjs` pattern, not a test framework).

**Spec:** `docs/superpowers/specs/2026-10-16-careers-design.md` (approved by EC 16 Oct 2026). Appendix A is the role copy of record, Appendix B the page wording; copy them verbatim.

## Global Constraints

- Visible name always `Me²`; "Me Squared" only in the email sender name and aria-labels. Australian English, sentence case, no all-caps labels.
- Banned words (grep all new copy): revolutionary, game-changing, supercharge, seamless, cutting-edge, unlock, guarantee, guaranteed.
- No `[[TBC` anywhere in the real build (`verify` fails it).
- Identity values only from `src/config/site.config.ts`; add `CAREERS_EMAIL: 'people@mesquaredagency.com'` there and a `{CAREERS_EMAIL}` placeholder to `fill()` in `src/config/index.ts`.
- Page titles and descriptions only in `src/data/routes.json`; descriptions ≤160 characters.
- Design: v0.15 "Lit" tokens and existing classes (`.wrap`, `.section`, `.on-dark`, `.on-paper`, `.kicker`, `.lede`, `.btn btn-light|btn-line`, `.dot`, `.tlink`). Coral only as light/the small square; `coral-deep` for coral text on paper. No card grids, chips, icon wells, gradient text.
- Custom class names must not be Tailwind utilities (avoid e.g. `sticky`, `hidden`, `block`, `grid`, `flex`, `table`, `group`, `border`, `shadow`, `ring`, `container`, `fixed`, `static`, `relative`, `absolute`, `visible`, `invisible`, `collapse`, `isolate`, `truncate`, `underline`, `uppercase`). Styles for a class passed into a child component use `:global(...)`.
- No new dependencies.
- Forms: never fields for financial, health or identity information; no date of birth, photo, gender, nationality or salary history.
- `src/content/careers.ts` imports nothing that only Vite can load (no `config/index.ts`, no `.astro`); the Worker imports it with an explicit `.ts` extension.
- Logs never contain names, emails, phone numbers or file names.
- CV: PDF, DOC or DOCX; ≤ 4 MB (4 × 1024 × 1024 bytes); signatures `%PDF` (25 50 44 46), `PK\x03\x04` (50 4B 03 04), `D0 CF 11 E0`.
- Line endings: keep each existing file's own (check `git ls-files --eol`); new files LF. Edit CRLF files with the Edit tool, never `sed -i`.
- Never push or merge to `main`; never send a real application to people@ without EC's yes.

## Review Focus

1. **A CV that's a PDF renamed, a 0-byte file, or exactly 4 MB:** a wrong signature is refused, a 0-byte file is refused as "choose your CV", and exactly 4 MB is accepted. Pinned in Task 2's checks.
2. **Someone applies with JavaScript off:** the form posts multipart to the same endpoint and lands on `/careers/thanks/` or `/careers/not-sent/`, CV attached. Pinned in Task 2 (multipart request) and Task 3 (form markup: `method`, `action`, `enctype`).
3. **Resend says no** (quota, rate limit, outage, key missing): the applicant sees the not-sent message with people@ as a link, and what they typed and the file they chose stay put. Pinned in Task 2 (429 → `{ok:false}`, 502) and Task 3 (failure leaves the field values in place).
4. **A preview link:** the subject starts `[Preview] ` so EC can tell test applications apart. Pinned in Task 2.
5. **`showCareers` off:** no `/careers/` pages, no footer link, no sitemap or llms.txt entries, and the Worker returns 404. Pinned in Task 4 (fixture build with the flag off) and Task 2 (handler with the flag off).
